# 推理说明

## 最终提交配置

最终提交版本为 `9b-e50e65-l75-s20-cfg1-seed42-promptfold`，使用：

| 项目 | 设置 |
| --- | --- |
| 基座模型 | `black-forest-labs/FLUX.2-klein-9B` |
| LoRA | `0.25×E50 + 0.75×E65` 的L75 |
| inference steps | 20 |
| CFG | 1.0 |
| denoising strength | 1.0 |
| seed | 42 |
| batch size | 1 |
| 输出 | 每张输入图像的26个目标视角RGB图像 |

`generate_images.py` 为与提交镜像一致的实际推理代码。

## PromptFold（固定提示词常量）

本方案的 26 个目标视角提示词固定不变，因此预计算对应的 `prompt_embeds` 和 `text_ids`，并以 BF16 常量随镜像保存。推理时直接加载这些文本条件常量，不再加载 tokenizer 和约 15.26 GiB 的文本编码器及其相关组件，只加载 DiT、VAE、LoRA 及常量，从而优化显存和初始化开销。

常量共包含 52 个张量、163,631,104 个元素。与原 9B BF16 提示词缓存逐元素比较，最大绝对误差为 0。该处理运行时直接作为模型输入传入推理链路，不生成、保存或使用任何派生的视觉、几何或语义中间表示，也不改变后续推理过程和输出结果，仅省略重复的文本编码过程。

其最初是为双种子 TTA（即一次推理调用中同时生成两个种子的结果，并在调用结束后像素平均）而准备：9B 模型采用 batch size 2 推理时显存压力显著增加，若同时加载文本编码器，将存在 OOM 风险，而提示词常量化可避免此问题。

虽然后续TTA被放弃（总分提高，人工视觉检查下却存在重影/伪影问题），但提示词常量化在单种子推理下仍能优化性能，故保留。

## 运行链路

完整链路为：读取单张RGB输入图像 → 加载官方挂载基座、单个L75和固定文本条件 → 对26个目标视角逐一采样 → 将模型输出直接保存为RGB图像。
